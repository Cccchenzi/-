## 二、项目愿景（一句话）

> 为需要回查学习资料的学生解决“资料分散、找到答案后难以确认出处”的痛点，通过个人知识库检索、带来源的问答和会话留存，相比逐份打开文件搜索，让答案与可核对的原文在同一条操作路径中呈现。

业务层关注学生是否更快完成查证；用户层关注上传、提问和核对来源；功能层再落实账号隔离、切片检索与会话保存。核心假设尚未经过真实学生验证，功能完成不能直接证明学习效率提高。

语义向量化与RAG生成均属Must。当前默认DeepSeek API（deepseek-flash）加本地qwen3-embedding:0.6b；密钥待本地填写，DeepSeek真实验收待完成。此前ChatGPT会员11项属历史证据，不计为DeepSeek通过；TF-IDF与摘录仅作降级。

### 需求冲突处理

教师提出的必需能力优先纳入验收；学生提出的新功能先关联痛点和故事，再判断是否进入本轮。涉及把资料发送给外部模型的选择，需由资料所有者确认处理授权。未经确认的新增范围进入候选清单，不静默变成Must。

### 下一轮确认事项

- 与教师确认：语义检索与RAG生成的评测题库、合格标准，以及Chroma预留接口的验收方式。
- 与学生确认：最常查找的资料类型、问题形式和核对出处的实际步骤。
- 与维护者确认：演示电脑、Python环境、资料规模和备份方式。
- 与资料所有者确认：哪些资料可导入，哪些资料允许交给所选模型服务处理。

需求变更记录至少包括提出者、原需求编号、改变原因、验收影响和处理结论。没有访谈记录或现场反馈时，只标为待确认候选，不写成“用户普遍要求”。

## 四、用户故事

| 编号 / 优先级 | 角色—目标—价值 | INVEST自查 |
| --- | --- | --- |
| US-01 / Must | 作为学生，我想注册和登录个人账号，以便将资料访问限制在本人空间。 | 目标小、可测；是其他故事的身份前提。 |
| US-02 / Must | 作为学生，我想创建、切换和删除知识库，以便按课程组织资料。 | 可单独验收；依赖US-01。 |
| US-03 / Must | 作为学生，我想批量上传PDF、Markdown和TXT并完成语义向量化，以便获得可检索资料及逐文件结果。 | 导入、切片、语义向量持久化同属Must；失败可重建。 |
| US-04 / Must | 作为学生，我想对当前库提问和追问，获得语义检索证据支持的生成回答及原文引用，以便核对答案和发现证据不足。 | 语义检索与生成均必需；DeepSeek真实验收待密钥。 |
| US-05 / Must | 作为学生，我想重开所属知识库的历史会话，以便继续之前的查阅过程。 | 可测试；依赖US-02、US-04的数据。 |
| US-06 / Should | 作为维护者，我想查看模型配置状态、实际回答模式和降级原因，以便定位故障并维护问答服务。 | 维护可观察性与降级增强；不替代US-04生成要求。 |
| US-07 / Could | 作为维护者，我想替换向量检索后端，以便后续评估Chroma的存储与检索能力。 | 本期预留可替换接口；Chroma接入另立迭代。 |

INVEST并非逐项打勾：身份和数据存在必要依赖，不能声称全部故事完全独立。通过固定接口和测试夹具降低依赖；US-04保留一个用户价值目标，研发任务再拆小。措辞、容量与性能目标可协商，但“本人资料、证据支持的生成、真实出处、异常有反馈”属于核心约束。

故事到界面：US-01对应登录；US-02对应知识库入口；US-03对应资料管理；US-04对应问答和引用面板；US-05对应历史会话。US-06、US-07为维护可观察性与接口扩展，不要求为普通学生增加复杂设置流程。

## 五、验收标准（Given–When–Then）

以下是需求验收标准，不等于所有输入已穷举。五个Must均含正常、边界和异常；语义向量化归US-03、检索生成归US-04。自动86项与历史边界14项、会员RAG 11项、旧版UI 13项分开记录，DeepSeek真实验收待补。

| 故事 / 场景 | Given 前置 | When 动作 | Then 可观察结果 |
| --- | --- | --- | --- |
| US-01 正常 / AC01 | 未注册的合法账号 | 注册后退出并重新登录 | 进入本人空间；能读取本人知识库列表。 |
| US-01 边界 / AC02 | 用户名和密码符合字符规则 | 分别提交用户名2、32与1、33字符，密码8、128与7、129字符 | 合法端点接受；越界返回400且不新增账号。 |
| US-01 异常 / AC03 | 已有账号或尚未登录 | 错误密码登录、重复注册、未登录读库 | 依次返回401、409、401；不泄露资料。 |
| US-02 正常 / AC04 | 用户已登录 | 创建并选择命名知识库 | 库出现在本人列表，初始文档及会话数为0。 |
| US-02 边界 / AC05 | 用户已登录 | 提交名称80、81字符和纯空白名称 | 80字符可建立；81字符及空白被拒绝。 |
| US-02 异常 / AC06 | A、B为不同账号 | B使用A的知识库ID读写或删除 | 返回404；A的文档、会话和库保持存在。 |
| US-03 正常 / AC07 | 本人知识库可用，嵌入服务就绪 | 批量上传可解析PDF、MD、TXT | 逐文件成功；原件可下载，非空片段及有限、同维语义向量持久化。 |
| US-03 边界 / AC08 | 每文件均可解析且未超其他限制 | 分别上传10个和11个文件 | 10个可逐件处理；11个整批拒绝且不新增资料。 |
| US-03 边界 / AC09 | 文件可解析、文字及页数未超限 | 分别提交20 MiB与20 MiB+1字节文件 | 前者不因体积拒绝；后者拒绝且不生成片段。 |
| US-03 异常 / AC10 | 一批含正常文件、损坏PDF、空文件和未知格式 | 提交该批文件 | 正常文件保存；其他逐件说明失败；无空片段和错误原件残留。 |

体积上限按20×1024×1024字节实现，界面标为20 MB。文件即使未超过体积限制，仍须符合格式、可提取文字、最多2000页和最多200万字符等约束；“刚好20 MB”不意味着任何内容都可接受。

## 五、验收标准（续）

| 故事 / 场景 | Given 前置 | When 动作 | Then 可观察结果 |
| --- | --- | --- | --- |
| US-04 正常 / AC11 | 当前库含明确事实，模型就绪 | 同义提问后用代词追问并打开引用 | 语义检索当前库证据；保留两轮记录，逐字引文可核对原文。 |
| US-04 边界 / AC12 | 会话有效 | 提交2000、2001字符及纯空白问题 | 2000字符进入问答处理；2001及空白返回400且不写入消息。 |
| US-04 边界 / AC13 | 资料不包含提问主题 | 提出无相关证据的问题 | 提示资料不足，返回空引用；不以常识补出资料答案。 |
| US-04 异常 / AC14 | 历史回答引用的文档已被删除 | 重新打开该条引用 | 标记原文不可用；不把后来上传的文档当作旧来源。 |
| US-05 正常 / AC15 | 库中已有问答 | 重开会话并重启应用后读取 | 问题、回答、引用按原顺序保留。 |
| US-05 边界 / AC16 | 同一用户有A、B两个库 | 切换到B并查看会话及提问 | B不显示A的会话，检索只使用B的资料。 |
| US-05 异常 / AC17 | 另一账号得知会话ID | 读取、发送消息或删除该会话 | 返回404；原会话内容不变。 |
| US-04 生成 / AC18 | DeepSeek密钥、地址和模型有效 | 模型返回结构化结论、编号与引文 | 校验编号及逐字原文后显示生成答案；DeepSeek真实调用待验收。 |
| US-06 边界 / AC19 | DeepSeek密钥未填或在线配置不完整 | 提出有证据的问题 | 不以配置代替连接成功；显示未就绪原因并回退摘录。 |
| US-06 异常 / AC20 | 已启用生成模型 | 响应不完整、调用超时或引文不真实 | 回退摘录并提示原因；不展示未验证生成或泄露令牌。 |

一致性规则：同库重复内容不新增片段；换嵌入模型须重建，旧向量及坏维度、NaN不可参与检索。删除文档同步删除向量，历史来源标失效；删除库清理所属资料与会话。各类资源由后端检查所有权。

结构化校验要求每条结论附证据，引用编号有效且引文逐字存在于原文。它能排除伪造出处，但不能自动证明结论受证据支持；事实正确性与支持度仍需独立人工评估，不承诺绝对消除幻觉。

## 六、边界与例外

本期处理本人导入的可提取文本，不做联网搜索。本地Qwen3-embedding生成稠密语义向量，持久化后按余弦相似度检索；TF-IDF仅在嵌入故障时降级并明确提示。Chroma保留替换接口，尚未实际接入。

| 本期不做 | 边界理由 |
| --- | --- |
| 不做OCR、图片问答、DOCX/PPTX导入 | 先稳定PDF/MD/TXT核心入口。 |
| 不做联网搜索和自动知识补全 | 明确回答的资料范围及来源。 |
| 不做多人共享、实时协作、手机原生App | 个人资料查证是本轮核心假设。 |
| 不做公网生产部署及完整安全认证 | 限于本地演示；公开部署需另立安全和运维需求。 |

| 异常场景 | 系统反应 / 用户下一步 |
| --- | --- |
| 扫描或加密PDF、乱码、纯空白 | 提示无法取得可用文字；用户先OCR、解密或转为UTF-8文本。 |
| 批次中部分解析失败 | 显示逐文件结果；保留成功项，允许仅重试失败项。 |
| 上传中断 | 提示请求失败，重新上传；不承诺断点续传。重复内容检测减少重试造成的重复资料。 |
| 嵌入故障、授权缺失或生成异常 | 保留原文并提示词法检索或摘录降级；允许重建向量，历史可查。 |
| 资料无证据、文档删除 | 资料不足或来源不可用提示；不伪造片段。 |

解析及默认嵌入在本机进行；DeepSeek生成会发送问题、检索片段和必要上下文，需确认资料授权。密钥只填本地.env的DEEPSEEK_API_KEY，不返回前端或提交Git；资料库及原件未加密。可选会员令牌的DPAPI保护不适用于.env密钥。

删除库属于不可撤回的数据清理，界面应要求确认并说明影响。项目当前不承诺完整审计日志、备份恢复服务或登录失败锁定；这些能力不得在答辩中当作已实现安全措施。

| MVP定义 | 内容 |
| --- | --- |
| 核心假设 | 学生使用个人资料问答和出处入口，比逐份检索文件更快完成查证，同时不降低事实正确性。 |
| 最小闭环 | 登录 → 创建库 → 上传并语义向量化 → 检索生成与追问 → 核对出处 → 重开历史；当前DeepSeek密钥待填，真实闭环待验收。 |
| 验证对象 | 查找并证实答案的完整任务，而不是页面数量或模型回答长度。 |

### 拟议验证方案（尚未实施）

邀请3名首次使用的学生，自愿参与并使用获授权资料。准备难度相近的A、B两套任务，每套包含2个可回答事实题、1个需结合片段的题和1个资料外题。由不参与计时的成员预先制定答案与证据标准；两套题不同，避免直接记住答案。

采取交叉顺序：有人先用原文件搜索完成A，再用知微完成B；其他人交换工具顺序和题组。3人无法完全平衡顺序影响，需在结果中保留该限制。统一简短说明和限时，记录开始、找到答案、完成原文核对的时间，以及错误、拒答和求助次数。

拟议通过条件：3人均在5分钟内独立完成一次核心闭环；工具查证时间中位数至少降低20%；事实正确率不低于基线；提交的出处均可定位，资料外题不编造事实。任一正确性或来源条件失败，先修正后复测，不以速度改善抵消错误。小样本只用于迭代决策，不外推总体效果。

证据分列：当前自动化86项通过，远端响应模拟、RSA与DPAPI真实执行；本轮DeepSeek适配以模拟回归验证，真实密钥未填。保留历史边界14项、会员RAG 11项及旧版UI 13项；会员模型为gpt-6.1-sol及本地qwen3-embedding:0.6b，合成库已清理，不能据此判定DeepSeek通过。

历史会员验收含同义、跨两文档、代词追问、未知及诱导编造拒答，也检查空库隔离与删除失效。三条生成均为dense、validated；11项含流程检查，并非11个质量样本。当前DeepSeek需单独重验；真人研究、总体正确率、性能及复杂边界仍待测。
