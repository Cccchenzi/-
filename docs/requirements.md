## 二 项目愿景

为需要回查课程笔记和论文的学生解决“资料分散、答案出处难以核对”的问题，通过本人资料检索、带引用的问答与会话留存，比逐份打开文件搜索更便于在同一页面完成答案查证。

业务目标是缩短“找到答案并确认出处”的过程；用户目标是上传、提问、核对和继续查阅；功能目标才是分块、向量检索、生成、引用与历史保存。效率改善属于待验证假设，评价方案见第七节。

### INVEST 结论

独立性并非全部满足：身份、知识库、资料与对话存在业务依赖，采用夹具和接口解耦。范围和参数可以协商；本期 US-01 至 US-06 有编号验收标准，US-07 接入前再细化。US-03、US-04 体量较大，开发前须分任务估时，不虚构尚未完成的工时估算。

项目 02 的对应关系：批量上传与切片向量化归 US-03；基于本人资料的多轮问答及引用溯源归 US-04；按知识库保存历史归 US-05。US-01、US-02 提供访问范围与资料组织前提。

## 五 验收标准

以下条件定义通过标准，不代表每个边界均已实测。接口测试检查响应和数据库；模型契约测试使用可控响应；真实模型测试另用固定资料和答案核对。任何摘录降级都不能代替语义检索与生成的正常验收。

### 测试前置与判定

准备互相隔离的账号 A、B 和知识库 K1、K2；资料包含可提取文字的 PDF、UTF-8 Markdown 和 TXT。为问答固定题目、标准答案和支持片段，包含同义问法、跨文档题、追问题和资料外题。容量边界使用合法且唯一的文件，避免格式、重复内容或提取字符数先触发其他限制。

| 编号与场景 | Given 前置条件 | When 触发动作 | Then 可观察结果 |
| --- | --- | --- | --- |
| AC-01；US-01；正常 | 账号 A 未注册，用户名与口令合法。 | 注册后退出，再用正确口令登录。 | 注册成功；再次登录后显示 A 的知识库列表。退出后的受保护请求返回 401。 |
| AC-02；US-01；边界 | 每组输入使用新的合法字符用户名。 | 分别提交用户名 2、32、1、33 字符及口令 8、128、7、129 字符。 | 用户名 2—32、口令 8—128 的组合被接受；越界输入返回 400 且不创建账号。 |
| AC-03；US-01；异常 | A 已有库、文档和会话，B 已登录。 | B 用 A 的资源 ID 发起读取或删除。 | 均返回 404；响应不含 A 的资料；A 的记录不变。 |
| AC-04；US-02；正常 | A 已登录，K1 含资料和会话。 | 创建 K2 并切换两库；取消一次删除 K1，再确认删除。 | 列表只显示选中库的资料。取消时 K1 不变；确认后其文档、向量、会话均不可再访问，K2 不变。 |
| AC-05；US-02；边界 | A 已登录，名称去除首尾空白后计数。 | 分别提交 1、80、0、81 字符的名称。 | 1 和 80 字符名称创建成功；空名与 81 字符名称返回 400，不新增库。 |
| AC-06；US-02；异常 | A 的 K1 含文档及历史，B 已登录。 | B 删除 K1 或一个不存在的知识库 ID。 | 均返回 404；A 的 K1、文档、向量与会话仍存在，B 的库也不改变。 |



账号口令测试采用合成数据；不在报告、日志或仓库内记录真实口令和 API 密钥。

## 六 边界与例外

### 本期范围与数据边界

本期提供本机浏览器应用与个人账号空间，支持可提取文字的 PDF、Markdown、TXT。不做 OCR、图片或表格视觉理解、Word/PPT 上传解析、联网搜索、多人共享协作、原生手机 App、公网生产部署和自动备份恢复。课程的 Word 与 PPT 是编写依据，不等同于应用支持上传这两类文件。

| 边界 | 处理约定 |
| --- | --- |
| 文件与容量 | 每批最多 10 份；每份 20 MiB；PDF 最多 2000 页；每份提取文本最多 200 万字符。MD/TXT 接受 UTF-8/BOM、GB18030。 |
| PDF 内容 | 纯扫描件无可提取文字时拒绝；混合扫描件只处理可提取文字。引用行号属于提取文本，不是 PDF 版面坐标。 |
| 检索与概览 | 语义检索最多 6 片段、每文档最多 3 片段；词法检索最多 5 片段。概览仅取目标文档开头最多 4 片段，不代表全文。 |
| 多轮上下文 | 当前仅对规则识别的短追问传递必要历史，最多最近 6 条、每条最多 1000 字符；独立新主题不沿用旧历史。 |
| 存储与扩展 | 当前在 SQLite 持久化向量，保留可替换向量检索接口。Chroma 完整接入、容量基准和迁移另立迭代。 |
| 外部服务与费用 | DeepSeek 处理问题、必要历史和检索片段；本地模型计算语义向量。账号隔离不等于独立计费，部署内各账号共用 API 额度。 |



### 异常反馈与降级

| 异常 | 系统反馈与后续操作 |
| --- | --- |
| 损坏、空白或超限文件 | 逐文件给出失败原因；可重导出或拆分后再上传。混合批次保留有效项；不承诺断点续传。 |
| 向量服务不可用 | 保留文档与片段并显示索引问题，恢复后重建。可用词法证据继续生成，须分别标明检索方式与回答模式。 |
| 生成调用或证据校验失败 | 标明失败阶段和未生成；最多展示 3 段、每段最多 450 字符的摘录，完整证据仍可查看。 |
| 网络中断或状态未知 | 显示请求失败和可重试入口；模型切换需回读确认，未知时不猜测是否保存。 |
| 删除和引用失效 | 删除库前确认影响；删除原文后保留历史快照并标明不可访问。无回收站与撤销保证。 |



## 七 优先级与 MVP

| 档位 | 本期取舍 |
| --- | --- |
| Must 必须有 | US-01 至 US-05：本人空间、知识库、批量导入与语义索引、资料问答与追问、引用溯源、按库历史；含最小错误反馈与 Chroma 替换接口。 |

### MVP 定义

核心假设：学生通过“答案加可定位出处”完成查证，比逐份搜索原文件更快，同时不降低事实正确性。MVP 验证的是整个查证任务，不能仅以页面可打开、生成文字较长或模型检查通过作为成功。

最小闭环：登录个人空间 → 创建课程库 → 上传并完成语义索引 → 提问和追问 → 打开引用核对原文 → 重开历史继续查阅。没有语义向量化、真实生成或来源核对，均未完成本项目核心闭环。

### 拟议用户验证

邀请 4 名首次使用的学生自愿参与，使用获授权资料。准备难度相近的 A、B 两套题，每套含 2 个事实题、1 个跨片段题、1 个资料外题，预先确定答案及出处。四人顺序分别为：原文件 A→知微 B；知微 B→原文件 A；原文件 B→知微 A；知微 A→原文件 B，以降低记忆与顺序影响。

每次从看到题目开始计时，到参与者提交答案并指出支持原文为止；资料外题以正确判定“资料不足”为完成。记录查证时间、答案正确性、出处可定位性、求助次数及操作失败。超时 10 分钟记为未完成，并以 600 秒计入用时，不能只保留成功样本。

拟议通过条件：首次流程单独计时，4 人均在 5 分钟内独立完成入口至出处核对；知微查证时间中位数比基线降低至少 20%；正确率不低于基线；所有提交出处均可定位，资料外题均不编造事实。正确性条件失败则修正后复测，不用速度提升抵消错误。

该研究尚未实施，以上阈值是本组待确认的验证目标；小样本结果仅支持下一轮取舍，不外推到所有学生或所有文档。

### 三至五分钟原型演示

以账户 A 进入 P01 → 在 P02 创建“示例资料库 A” → P03 模拟上传三个有效文件 → P04 提问并观察带引用的回答 → P05 核对原文 → 返回 P04 追问 → P06 重开历史 → P07 演示模型失败回退 → 切换账户 B 查看隔离效果。每步指出表中的 US 和 AC 编号。

原型中的账号、上传、索引与生成均为模拟。刷新会清空演示状态；P06 的历史恢复只验证本页内的流程，真实跨重启持久化仍按 AC-16 验收。低保真原型目前不覆盖 US-06 模型选择增强，实际界面已提供该功能；本期五个 Must 均有页面对应。

### 三至五分钟报告讲解

先用一句话说明谁在什么任务中遇到困难，再说明课程五项能力如何组成闭环；选 AC-11 展示正常验收，选 AC-13 展示异常处理；最后说明本期不做什么，以及第七节如何用查证任务验证核心假设。
