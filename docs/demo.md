# 课堂演示与验收

## 演示准备

按根目录 README 在 VS Code 启动服务。准备一个新账号，使用 `sample_docs/` 中的三个文件；这些文件包含明确标记的演示资料和虚构计划，不是调查数据。默认本地模式不需要 API Key。快速路径为：创建账号 → 创建知识库（如尚无）→ 点击“导入示例”→ 发送问题 → 点击 `[1]` 引用核对原文；也可使用下面的手动批量上传路径展示导入能力。

可使用以下事实检查演示是否正确：项目代号为“青竹-27”，演示里程碑为“2026 年 11 月 6 日”，课堂验证计划邀请“3 位同学”。RAG 演示评估集计划为 12 个可回答问题、4 个资料外问题和 4 个多轮追问，共 20 个。以上是样例内容，不能写成实际评测结果。

## 3–5 分钟闭环演示

| 时间 | 操作 | 讲解要点 / 对应需求 |
| --- | --- | --- |
| 0:00–0:30 | 注册/登录，创建“软件工程学习资料”知识库 | 每个账号拥有自己的资料空间，US-01、US-02 |
| 0:30–1:15 | 一次上传三个样例文件，查看成功、片段数和文档列表 | 导入后自动解析和切片，US-03；默认 TF-IDF 为词法向量检索 |
| 1:15–2:00 | 问“青竹-27 的里程碑日期是什么？”，展开引用并查看来源原文 | 答案应关联样例计划的真实文字，US-04 |
| 2:00–2:30 | 在同一会话追问“它的核心闭环包含哪些步骤？” | 展示同一会话的上下文与连续记录，US-04 |
| 2:30–3:00 | 问“撒哈拉沙漠今天的气温是多少？” | 完全资料外的问题应提示资料不足；不展示虚构出处，US-04 |
| 3:00–3:30 | 新建会话，再打开刚才的历史会话；刷新页面 | 同一知识库保留问答，US-05 |
| 3:30–4:15 | 重复上传其中一份文件，上传一个不支持的文件，查看提示 | 演示边界和异常反馈，US-03 |
| 4:15–5:00 | 说明模型配置、降级及下一阶段评估计划 | 本地可运行；外部模型是可选项；Chroma 尚是扩展点 |

若模型没有启用，应直接说明“当前展示本地检索摘录模式”；不要把摘录拼接宣称为大模型生成。若启用了模型，应说明片段和上下文会发送给该服务商。

可追加弱证据演示：“项目的预算是多少？”样例文件明确没有预算数字。词法检索可能命中讨论预算缺失的文字；此时正确结果是资料不足或指出未记载，不能编造金额。该场景用于人工检查生成内容，不等同于简单的零相关词拒答测试。

## 验收矩阵

| 验收项 | 方法 | 合格条件 |
| --- | --- | --- |
| 注册、登录、退出 | 自动化 + 浏览器 | 合法操作可用；错误密码及未登录请求被拒绝 |
| 账号隔离 | 自动化 | B 无法读写 A 的库、文档、会话、引用 |
| 知识库隔离 | 自动化 + 浏览器 | 同一账号不同库的问答与会话不混用 |
| PDF / MD / TXT | 自动化 + 浏览器 | 可解析的三类文档生成真实片段 |
| 批量错误处理 | 自动化 | 同批有效文件成功，空白、损坏、不支持格式逐文件失败 |
| 重复上传 | 自动化 + 浏览器 | 相同内容不新增片段，显示重复结果 |
| 引用溯源 | 自动化 + 浏览器 | 引用属于当前库，文字来自对应片段，可打开原文 |
| 资料外问题 | 自动化 + 浏览器 | 提示资料不足，不伪造引用 |
| 多轮会话 | 自动化 + 浏览器 | 问答按顺序保留；追问仍关联当前会话 |
| 持久化 | 自动化 | 同一数据目录重开应用后，资料和历史仍可读 |
| 词频向量与迁移 | 自动化 | 上传保存稀疏词频；旧数据库补列后仍可检索既有资料 |
| 可替换检索接口 | 自动化 | 注入替代检索实例可用；越出当前库的结果不能变成引用 |
| 模型失败降级 | 自动化（模拟） | 超时/无效返回不破坏问答；能回退摘录 |
| 模型配置完整性 | 自动化（模拟） | 仅填写密钥不发起模型调用；提示配置不完整并显示本地片段 |
| 用户体验与性能 | 待真实测量 | 依据 requirements.md 记录实际耗时和失败案例 |

自动化运行：在项目根目录执行 `python -m unittest discover -s tests -v`。以实际终端结果作为测试证据；本文件不预填通过数量。

## 需求答辩说明

核心假设不是“系统有五个功能”，而是“学生能更快找到并核对所需学习资料”。演示只证明闭环能运行，真正验证假设还需要让同学使用真实资料、记录耗时与错误，并比较原有查找方式。

老师提供的模板另有正式需求报告和低保真原型要求。本项目随代码提供需求、架构与演示说明；这些材料可帮助整理报告，但运行界面与工程文档不能自动替代规定格式的报告和原型文件。提交前请补齐真实组员信息、访谈/观察依据、实测结果以及所需低保真原型。
