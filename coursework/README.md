## 需求范围与完成状态

五个 Must 用户故事保持一致：US-01账号，US-02知识库，US-03批量导入与语义向量化，US-04基于语义检索证据的生成、追问与出处，US-05会话历史。

**语义向量化和RAG生成均属于本轮Must。** V1.3默认改为DeepSeek API生成加本地Ollama嵌入，模型为 `deepseek-flash` 与 `qwen3-embedding:0.6b`。工程实现了稠密向量持久化、模型变更后重建、语义检索、结构化生成调用与逐字引文校验；TF-IDF与摘录仅作明确标注的降级。DeepSeek适配使用模拟回归，密钥待用户本地填写，真实生成验收尚未完成。此前ChatGPT会员 `gpt-6.1-sol` 的11项真实检查保留为历史证据，不算DeepSeek通过。

当前配置为 `RAG_PROVIDER=deepseek`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`、`DEEPSEEK_MODEL=deepseek-flash`、`EMBEDDING_PROVIDER=ollama`。申请密钥后仅填入本地 `.env` 的 `DEEPSEEK_API_KEY`；不在讲稿、报告、截图或Git中填写真实密钥。

US-06的Should范围是维护配置状态、回答模式和降级原因的可观察性与维护增强；US-07的Could范围仅为Chroma后端接入，目前保留可替换接口。语义嵌入已经纳入Must，并非后续可选升级。

资料解析及默认语义嵌入在本机进行；DeepSeek生成会发送问题、检索片段和必要上下文给DeepSeek，需确认资料授权。API密钥不返回前端，不提交Git；`.env`不自动享有可选会员OAuth令牌的DPAPI加密保护。

| 当前DeepSeek与待验证 | 适配用模拟回归；待本地密钥后验证真实连接、生成、综合、追问及拒答，另需用户研究和性能评估 | DeepSeek已真实接通，或总体准确率、满意度、效率提升已有结果 |

**自动86项与历史边界14项、会员RAG 11项、旧版UI 13项分别统计，不合并为unittest数量。** 历史会员11项含连接、上传和隔离等流程检查，并非11个质量样本，也不验证DeepSeek。真实本地嵌入单例另记，不是总体准确率基准。首次请求29.42秒含冷启动，不证明预热性能达标。原型资料、回答与行号均为演示，性能和效率阈值仍是拟议目标。

历史ChatGPT会员生成核对了三例：“练习成果”同义提问回答教务系统提交；跨文档回答渠道及魏老师验收；代词追问回答四分钟。四条结论均有对应原文的连续逐字引文，未知预算和诱导编造均拒答。该合成测试库已清理。上述结果属于当时的会员模型；DeepSeek取得密钥后须单独重复这些检查，有限用例也不保证零幻觉。

在项目根目录、已激活虚拟环境后分别运行：

```powershell
python -m unittest discover -s tests -v
python tools/check_boundaries.py
```

具体边界测试说明见 [tools/README.md](../tools/README.md)。补充结果文件属于测试输出，不应包含真实用户资料或密钥。
