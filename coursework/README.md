## 需求范围与完成状态

五个 Must 用户故事保持一致：US-01账号，US-02知识库，US-03批量导入，US-04基于证据的检索增强生成、追问与出处，US-05会话历史。

**RAG生成是项目池要求，属于US-04的Must范围。** 当前工程已提供模型调用接口和引用检查，默认使用本地TF-IDF检索与原文摘录作为可运行降级路径。真实模型服务连通性和回答质量尚未完成验收，因此不能宣称US-04已经完整验收，也不能用摘录模式或固定规则演示替代生成要求。

US-06的Should范围仅是维护配置状态、实际回答模式和降级原因的可观察性与维护增强；US-07的Could范围为Chroma及语义嵌入升级。当前只有可替换检索接口，尚未接入Chroma。

## 原型演示

双击 `prototype.html`，或在浏览器打开该文件。它不依赖服务器，不读取真实文件，不调用模型，不提供真实身份认证，也不将内容保存到磁盘。演示数据只保留在当前页面内存中，刷新或点击“重置全部演示”后清空。

| 页面 | 内容 | 需求 |
| --- | --- | --- |
| P01 入口与身份 | 选择演示账户A/B，模拟登录成功或失败 | US-01 |
| P02 知识库 | 创建、选择、删除和空状态 | US-02 |
| P03 批量上传 | 模拟有效文件、部分失败及输入边界 | US-03 |
| P04 提问与回答 | 固定规则模拟生成、追问、引用、拒答和降级 | US-04 |
| P05 来源核对 | 来源文件、原文片段及位置 | US-04 |
| P06 会话历史 | 当前库的历史列表、重开、新建与删除 | US-05 |
| P07 边界与异常 | 资料不足、模型失败、输入错误、空库和账户隔离入口 | US-01～US-05 |

推荐路径：选择演示账户A → 创建“示例资料库A” → 模拟上传3个有效文件 → 填入“里程碑安排”并发送 → 点击`[1]`进入P05核对 → 追问“该怎么验收” → P06重开历史 → P07演示拒答和回退。这里使用“示例项目甲”的合成资料，与工程目录中的“青竹-27”样例不是同一套演示内容。

## 证据边界

| 类型 | 已有证据 | 不能据此声称 |
| --- | --- | --- |
| 原型模拟 | P01–P07的固定规则和内存状态可用于流程讲解 | 真实登录、文件解析、网络请求或模型生成已执行 |
| 工程自动化实测 | 28项API与集成测试通过；真实Flask接口、SQLite、文件解析与权限检查；模型返回使用模拟 | 真实模型质量、完整浏览器体验或全部输入已验收 |
| 独立边界实测 | 14项检查通过：10/11文件、实际20 MiB与超1字节PDF、用户名/密码长度端点、2000/2001字符问题 | 200万字符、2000页、所有字符集或复杂PDF均已覆盖 |
| 待验证 | 真实模型运行与质量、完整浏览器人工验收、性能、真实学生对照任务 | 已取得准确率、满意度或效率提升结果 |

28项自动化测试与14项独立边界检查是两套记录，**不合称42个unittest**。原型中的日期、资料、回答与行号都是演示内容；报告中的性能和效率阈值是拟议目标，不能填作实测结果。

在项目根目录、已激活虚拟环境后分别运行：

```powershell
python -m unittest discover -s tests -v
python tools/check_boundaries.py
```

具体边界测试说明见 [tools/README.md](../tools/README.md)。补充结果文件属于测试输出，不应包含真实用户资料或密钥。

## 发布与提交核对

- 核对Word报告与原型P01–P07编号、US编号和实际按钮名称一致。
- 用真实信息补齐小组字段和提交日期，并核对已给定的GitHub链接；没有访谈则保留“尚未开展”。
- 真实模型验收补齐前，保留US-04的未验收说明；不要把生成要求改成可选项。
- 公开仓库不提交API密钥、本机数据目录、真实用户上传资料或个人计算机绝对路径。
- 正式答辩前按讲稿完整排练两段3–5分钟演示，分别记录需要改进的流程和待验证事项。
